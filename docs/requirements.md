# AviUtl2 MCP Phase 1 要件定義書（承認済み・設計追記あり）

## 1. 文書状態

- フェーズ: Phase 1 要件定義
- 状態: ユーザー承認済み（2026-07-18）
- Phase 2追記: 複数インスタンス選択とat-most-once受入基準を明確化し、2026-07-18に承認済み
- 前提仕様: [Phase 0 仕様書](specification.md)
- 対象環境: Windows 64-bit、AviUtl ExEdit2 2.1.3a

## 2. ゴール

MCP 対応AIクライアントが、起動中の AviUtl2 に対して以下を実行できることをV1のゴールとする。

1. 編集状態と利用可能な能力を把握する。
2. 現在のプロジェクト、シーン、タイムラインを構造化データとして参照する。
3. SDK が公開する範囲の編集を、安全な Undo 単位で実行する。
4. PSDToolKit2 と GCMZDrops を使う立ち絵、音声、字幕ワークフローを操作・検証する。
5. 指定フレームのプレビューとログを使って、操作結果を自動検証する。

## 3. スコープ

### 3.1 V1必須

- ローカル stdio MCP サーバー
- AviUtl2 汎用ブリッジプラグイン
- 現在ユーザーだけが接続できるローカル IPC
- 状態、能力、プロジェクト、タイムライン、オブジェクト、エフェクトの参照
- SDK 公開範囲のオブジェクト、レイヤー、設定項目編集
- 複数編集、dry-run、編集リビジョン検証、Undo
- PSDToolKit2 と GCMZDrops の操作・診断
- プレビュー画像取得
- 構造化ログと診断レポート
- 単体、統合、MCP、AviUtl2実機テスト
- インストール、アンインストール、MCP設定手順

### 3.2 V1実験機能

以下は公開 SDK で直接操作できることが確認できていないため、能力検出と実機検証に合格した場合のみ有効化する。

- プロジェクトの新規作成、開く、別名保存
- 再生開始、停止
- 既存オブジェクトへのエフェクト追加、削除、並べ替え
- オブジェクト分割、長さ変更、トラック・キーフレーム編集
- シーンの追加、削除、切り替え
- 出力開始、進捗取得、キャンセル

実験機能が無効な環境では、未実装を成功として返さず `capability_not_available` を返す。

### 3.3 対象外

- AviUtl2 や PSDToolKit2 本体の改変
- PSDToolKit2 の非公開 IPC への依存
- 任意のシェルコマンド実行
- インターネット越しのリモート操作
- ユーザーの既存制作プロジェクトを使った破壊的自動テスト

## 4. 用語

| 用語 | 定義 |
|---|---|
| ブリッジ | AviUtl2 プロセス内で SDK を呼び出す汎用プラグイン |
| MCPサーバー | stdio MCPを公開し、ブリッジへ要求を転送するプロセス |
| ロケーター | SDKハンドルを保持せず、オブジェクトを要求ごとに再解決する識別情報 |
| 編集リビジョン | 読み取り後に対象が変更されていないことを検証する値 |
| dry-run | 変更を適用せず、対象、検証結果、予定変更を返す実行方式 |
| 能力 | 現在のバージョンと状態で安全に実行できる操作 |

## 6. 機能要件

### 6.1 接続・状態・能力

- **FR-CON-001** MCPサーバーはAviUtl2未起動時にも起動し、未接続状態を返す。
- **FR-CON-002** ブリッジが後から起動した場合、MCPサーバーは再起動なしで接続できる。
- **FR-CON-003** 状態応答はMCPサーバー、ブリッジ、AviUtl2、PSDToolKit2、GCMZDropsの検出結果を区別する。
- **FR-CON-004** AviUtl2の編集、再生、出力状態を返す。
- **FR-CON-005** 能力応答は操作ごとに `available`、理由、制約を返す。
- **FR-CON-006** プロトコルバージョン不一致時は接続を拒否し、両バージョンを返す。
- **FR-CON-007** 複数のAviUtl2インスタンスが存在する場合は候補を列挙し、明示選択なしに編集対象を自動決定しない。

### 6.2 プロジェクト・シーン

- **FR-PRJ-001** プロジェクトパス、未保存状態、シーンID、名称を取得する。
- **FR-PRJ-002** 解像度、フレームレート、サンプリングレート、現在フレームを取得する。
- **FR-PRJ-003** 選択レイヤー、選択範囲、表示フレーム・レイヤー範囲を取得する。
- **FR-PRJ-004** プロジェクト未作成時は空の成功結果にせず `project_not_open` を返す。
- **FR-PRJ-005** プロジェクトパスは公開SDKまたはGCMZDrops共有メモリから取得し、未保存による空パスとプロジェクト未作成を区別する。
- **FR-PRJ-006** 名前付きの現在プロジェクトを`expectedRevision`付きで保存し、既存のsave callbackによる完了を確認する。未保存プロジェクトではdialogを開かず`project_path_required`を返し、保存だけではcontent revisionを増加させない。

### 6.3 タイムライン参照

- **FR-TLN-001** 指定したレイヤー範囲とフレーム範囲に交差するオブジェクトを列挙する。
- **FR-TLN-002** レイヤー番号、名称、表示状態、ロック状態を返す。
- **FR-TLN-003** オブジェクトのロケーター、名称、開始・終了フレーム、長さ、選択状態を返す。
- **FR-TLN-004** 取得量をレイヤー、フレーム、件数、詳細度で制限できる。
- **FR-TLN-005** オブジェクトのエイリアス、エフェクト一覧、設定項目、有効・ロック状態を詳細取得できる。
- **FR-TLN-006** 区間数と区間開始フレーム、指定フレームのトラック・チェック値を参照できる。
- **FR-TLN-007** エフェクト、項目型、モジュール、フォント、パレットを列挙できる。
- **FR-TLN-008** 読み取り結果に編集リビジョンを付与する。

### 6.4 タイムライン編集

- **FR-EDT-001** SDKが対応するメディアファイルからオブジェクトを作成する。
- **FR-EDT-002** エフェクト名からオブジェクトを作成する。
- **FR-EDT-003** UTF-8のオブジェクトエイリアスデータから単一・複数オブジェクトを作成する。
- **FR-EDT-004** 作成前にレイヤー、フレーム、長さ、衝突、ファイル存在を検証する。
- **FR-EDT-005** ロケーターから再解決したオブジェクトを移動、削除、名称変更する。
- **FR-EDT-006** 既存エフェクトの項目値、有効状態、ロック状態を変更する。
- **FR-EDT-007** レイヤーの名称、表示状態、ロック状態を変更する。
- **FR-EDT-008** カーソル、表示位置、選択範囲を変更する。
- **FR-EDT-009** `expectedRevision`が不一致なら何も変更せず `revision_conflict` を返す。
- **FR-EDT-010** `dryRun=true`なら何も変更せず、対象と予定変更を返す。
- **FR-EDT-011** バッチ内の全操作を1回のSDK編集セクションで実行し、1 Undo単位にする。
- **FR-EDT-012** バッチの事前検証失敗時は編集を開始しない。
- **FR-EDT-013** 編集中、再生中、出力中などの状態競合を識別して返す。
- **FR-EDT-014** オブジェクト中間点を作成・削除・移動し、全object応答で0始まりの区間indexと1始まりの開始frameを返す。
- **FR-EDT-014** 操作後の対象ロケーターと新しい編集リビジョンを返す。
- **FR-EDT-015** 編集開始後にSDK操作が失敗した場合、成功として扱わず、部分適用の有無、適用済み操作、再取得状態、Undo推奨を返す。

### 6.5 PSDToolKit2・GCMZDrops

- **FR-PSD-001** PSDToolKit2とGCMZDropsの導入状態を個別に検出する。
- **FR-PSD-002** GCMZDrops外部APIのMutex、共有メモリ、APIバージョン、対象ウィンドウを診断する。
- **FR-PSD-003** PSD/PSBを指定位置へ投入し、作成されたPSDToolKit2オブジェクトを返す。
- **FR-PSD-004** `最初に置くやつ@PSDToolKit` の有無、配置順、尺を検証する。
- **FR-PSD-005** 不足時は初期化オブジェクトを安全な位置へ作成できる。
- **FR-PSD-006** PSDオブジェクトのキャラクターID、ファイル、レイヤー状態を取得・更新する。
- **FR-PSD-007** WAV、TXT、LABの存在と同名対応を検証する。
- **FR-PSD-008** GCMZDrops経由で `セリフ準備@PSDToolKit` を作成し、公開SDKの字幕エイリアス作成と組み合わせて音声・字幕を構成する。
- **FR-PSD-009** 目パチ、口パク（開閉・あいうえお）、パーツ上書きの必須エフェクトと参照IDを検証する。
- **FR-PSD-010** PSDToolKit2固有名称を固定インデックスだけで判定せず、エイリアスとエフェクト列挙結果で確認する。
- **FR-PSD-011** GCMZDrops APIが2つ目以降のAviUtl2インスタンスで無効な場合、その理由を返す。
- **FR-PSD-012** PSDToolKit2の非公開IPCが変更・停止しても、MCPサーバーとブリッジの基本機能は動作する。
- **FR-PSD-013** GCMZDropsを使う複合操作は投入後に生成物を再検索し、タイムアウトまたは一部生成時は部分適用として結果を報告する。

### 6.6 プレビュー

- **FR-PRV-001** 現在のシーンの指定フレームをレンダリングする。
- **FR-PRV-002** 幅、高さ、フレーム番号、MIME typeを伴う画像コンテンツを返す。
- **FR-PRV-003** レンダリング要求を編集ロック中に待機してデッドロックさせない。
- **FR-PRV-004** 出力中などレンダリング不可の場合は理由を返す。
- **FR-PRV-005** 非同期レンダリングの完了待ちはSDKの読取・編集ロック外で行い、タイムアウト後も遅延コールバックのメモリ安全性を保つ。

### 6.7 診断・ログ

- **FR-DIA-001** MCP、IPC、ブリッジ、AviUtl2のログを相関IDで追跡できる。
- **FR-DIA-002** MCP stdio の標準出力へログを出さず、標準エラーまたはファイルへ出す。
- **FR-DIA-003** AviUtl2の最新ログを件数、期間、レベルで絞り込む。
- **FR-DIA-004** PSDToolKit2のパイプ終了、キャッシュ未検出、エフェクト未検出を既知パターンとして分類する。
- **FR-DIA-005** 診断結果は検出事項、根拠、影響、推奨対処を区別して返す。
- **FR-DIA-006** 秘密情報やファイル内容全体を既定でログへ記録しない。

### 6.8 配布・運用

- **FR-OPS-001** MCPサーバーとブリッジを再現可能なコマンドでビルドできる。
- **FR-OPS-002** ブリッジをAviUtl2へ導入・削除する手順を提供する。
- **FR-OPS-003** Codex、Claude Desktop、VS Code等で使えるstdio設定例を提供する。
- **FR-OPS-004** 設定検証コマンドまたは自己診断ツールを提供する。
- **FR-OPS-005** GitHub Actionsでビルドと自動テストを実行する。

## 7. 非機能要件

### 7.1 安全性

- **NFR-SAF-001** SDKのオブジェクト・エフェクトハンドルをコールバック終了後まで保持しない。
- **NFR-SAF-002** 更新はSDK編集セクション、参照は読取セクション内で行う。
- **NFR-SAF-003** シーン設定などUndo非対応操作は既定で無効にする。
- **NFR-SAF-004** 削除・再構築はdry-runと対象再検証に対応する。
- **NFR-SAF-005** 実機自動テストは専用プロジェクトだけを対象にする。

### 7.2 セキュリティ

- **NFR-SEC-001** 名前付きパイプは現在のWindowsユーザーだけに接続を許可する。
- **NFR-SEC-002** IPC要求サイズ、文字列長、配列件数、画像応答サイズに上限を設ける。
- **NFR-SEC-003** パスは絶対パスへ正規化し、存在・種類・許可拡張子を検証する。
- **NFR-SEC-004** MCPから任意コマンド、任意DLLロード、任意メモリ読み書きを公開しない。
- **NFR-SEC-005** 外部ネットワーク待受を既定で作成しない。

### 7.3 性能・制限

- **NFR-PER-001** ローカル接続済みの状態取得は通常2秒以内に完了する。
- **NFR-PER-002** 100オブジェクト以下のタイムライン概要取得は通常5秒以内に完了する。
- **NFR-PER-003** 単一編集は通常10秒以内、プレビューは通常30秒以内に完了する。
- **NFR-PER-004** 既定の一覧上限を100件とし、最大1000件を超える要求を拒否する。
- **NFR-PER-005** タイムアウト値は操作種別ごとに設定可能にする。

### 7.4 信頼性

- **NFR-REL-001** AviUtl2またはMCPサーバーの再起動後に再接続できる。
- **NFR-REL-002** IPC切断をMCPプロセス全体のクラッシュにしない。
- **NFR-REL-003** 要求ごとに一意な相関IDを付与し、重複応答を防止する。
- **NFR-REL-004** タイムアウト後に結果不明となった編集を、状態再照会で判定できる。
- **NFR-REL-005** 未知のSDK・プラグイン版では安全側に能力を無効化する。
- **NFR-REL-006** 変更IPC要求は同一bridge epoch内でclient instance IDとrequest IDによりat-most-onceに処理し、再接続後の同一要求で編集を重複適用しない。

### 7.5 互換性・保守性

- **NFR-CMP-001** AviUtl ExEdit2 2.1.3a、Windows 64-bitを基準環境とする。
- **NFR-CMP-002** SDK、PSDToolKit2、GCMZDropsの版差を能力検出で吸収する。
- **NFR-CMP-003** MCP層、IPC層、AviUtl2 SDKアダプター、PSD連携を分離する。
- **NFR-CMP-004** 公開プロトコルと設定ファイルにバージョンを持たせる。
- **NFR-CMP-005** UTF-8、Windowsパス、日本語のエフェクト名・オブジェクト名を保持する。

### 7.6 テスト品質

- **NFR-TST-001** 重要な編集、ロケーター、リビジョン、バッチ、PSD検証をAAA構造の単体テストで覆う。
- **NFR-TST-002** IPCの正常、切断、再接続、タイムアウト、サイズ超過を統合テストする。
- **NFR-TST-003** MCPのinitialize、tools/list、resources/list、prompts/list、代表tool callを自動テストする。
- **NFR-TST-004** 実機テストで追加、参照、変更、Undo、削除、プレビューを検証する。
- **NFR-TST-005** PSD実機テストでPSD追加、初期化、音声・字幕、構成検証を確認する。

## 8. 共通エラー要件

最低限、次の安定したエラーコードを定義する。

| コード | 意味 |
|---|---|
| `aviutl_not_running` | AviUtl2が起動していない |
| `bridge_not_connected` | ブリッジへ接続できない |
| `instance_ambiguous` | 対象AviUtl2が複数あり明示選択が必要 |
| `invalid_argument` | 入力値間の制約または対象instanceの整合性に違反した |
| `cursor_invalid` | cursorが現在の状態、query、期限またはserver epochと一致しない |
| `bridge_busy` | ブリッジの接続または待ち行列が上限に達した |
| `request_id_conflict` | 同じIPC request IDに異なるpayloadが指定された |
| `request_expired` | 変更request IDの安全な再送受付期間が終了した |
| `request_result_evicted` | 変更済みだが完全応答cacheが失効し、状態再取得が必要 |
| `operation_cancelled` | commit point前に取消され変更されなかった |
| `protocol_incompatible` | MCPサーバーとブリッジのprotocol major範囲が一致しない |
| `project_not_open` | 編集可能なプロジェクトがない |
| `edit_not_available` | SDK状態不明、layer lock、編集section拒否などで編集できない |
| `project_playing` | 再生中のため編集できない |
| `project_saving` | 保存・出力中のため編集できない |
| `capability_not_available` | 現在の環境で操作を提供できない |
| `object_not_found` | ロケーターを再解決できない |
| `object_ambiguous` | 複数候補があり一意に解決できない |
| `revision_conflict` | 読み取り後に編集状態が変化した |
| `object_collision` | 作成・移動先で衝突した |
| `invalid_effect_item` | エフェクトまたは項目が存在しない |
| `invalid_media_file` | ファイルが存在しない、または非対応 |
| `psdtoolkit_not_available` | PSDToolKit2が利用できない |
| `gcmzdrops_not_available` | GCMZDrops外部APIが利用できない |
| `request_too_large` | IPCまたはMCP要求が上限を超えた |
| `operation_timeout` | 操作が期限内に完了しなかった |
| `partial_operation` | 操作の一部が適用され、事後状態の確認またはUndoが必要 |
| `internal_error` | 分類できない内部エラー |

エラー応答はコード、人間向けメッセージ、相関ID、再試行可否、関連詳細を返す。

## 11. 敵対的レビュー結果

### 11.1 指摘と修正

- **要求過多で一覧取得が巨大化する**: 範囲、件数、詳細度と最大1000件の制限を追加した。
- **SDKハンドルをMCP IDとして保持する危険**: ロケーター再解決と編集リビジョンを必須化した。
- **dry-run後に対象が変わる競合**: `expectedRevision`不一致時の全変更拒否を追加した。
- **バッチ途中失敗で部分適用される**: 全操作の事前検証を要求した。ただしSDK編集開始後の完全ロールバック可否はPhase 2で明示する。
- **PSDToolKit2内部IPCへの密結合**: 公開SDKとGCMZDrops公開APIだけを依存境界にした。
- **GCMZDrops障害が全機能を停止させる**: 基本機能とPSD音声投入の能力を分離した。
- **実験機能が暗黙に成功扱いになる**: 能力無効化と安定エラーを要求した。
- **自動テストが既存プロジェクトを破損する**: 専用プロジェクト限定を受け入れ基準にした。
- **stdioログでMCP通信が破損する**: 標準出力をプロトコル専用にした。
- **大きなプレビューでIPCが枯渇する**: 画像応答サイズ上限を非機能要件へ追加した。

### 11.2 Phase 2で解決する設計課題

1. ロケーターのフィンガープリントと編集リビジョンの算出方式
2. バッチ編集開始後にSDK操作が失敗した場合の補償方式
3. 名前付きパイプのメッセージフレーミングと画像転送方式
4. MCPサーバーとブリッジの起動順・再接続状態遷移
5. PSDToolKit2の日本語名称と版差を吸収する検出方式
6. MCPツールの詳細JSON Schemaと応答モデル
7. プレビューのPNG変換位置と最大サイズ
